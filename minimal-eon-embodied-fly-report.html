制造物联网技术大作业 · 最小具身演示方案

最小 Eon 式具身果蝇复现工作清单与调研报告

目标不是复刻 Eon 内部完整系统，而是做一个课堂可运行的“脑模型读出 + 虚拟身体 + 环境反馈”最小闭环。 建议方案：用 FlyGym/NeuroMechFly 做身体和 MuJoCo 场景，用 Nature 全脑 LIF 模型的离线结果或小规模在线调用做行为门控，演示觅食、遇到虚拟尘埃后梳理、接触食物后进食。

范围界定

推荐复现口径

“Eon-inspired minimal embodied fly”，即复现 Eon 的系统思想：感觉输入进入脑模型，脑模型读出低维行为信号，身体控制器执行动作，环境状态再反馈。

不承诺内容

不承诺实时运行 14 万神经元全脑模型，不承诺复现 Eon 未公开的桥接代码，不承诺实现完整视觉系统和真实神经元到关节力矩映射。

课堂验收

一段可播放演示：虚拟果蝇在场景中前进或转向，状态面板显示 taste/dust/brain readout/behavior，行为切换逻辑能被解释。

核心建议： 最小演示不要把“全脑 LIF”放进实时物理环路里硬跑。更稳的做法是先用 Shiu 等人的模型离线生成 lookup table： sugar input 对应 MN9 feeding readout，mechanosensory input 对应 grooming readout，再在 FlyGym 主循环中按 10-20 Hz 查询这些读出。

Eon 公开方案的可复现信息

Eon 在 2026-03-10 的技术文章中说明，其虚拟具身果蝇是对已发表组件的集成：Shiu et al. 的全脑 LIF 模型、FlyWire 连接组、Lappalainen et al. 的视觉通路模型、NeuroMechFly v2 虚拟身体和 MuJoCo 物理引擎。 Eon 自述目前只实现了少量感觉输入和少数行为，脑-身体接口仍是简化的低维读出层。

Eon 元素 公开描述 最小复现处理
虚拟场景 演示中使用不可见 taste cues 导航到食物源，并设置虚拟尘埃触发梳理。 用二维食物点和 dust 计时器/区域触发即可，不必复刻 Eon 场景美术。
脑模型 基于 Shiu et al. 的 LIF 全脑模型，约 14 万神经元和 5,000 万突触，递质预测决定突触符号。 用离线 lookup table 或小规模 Brian2 调用输出 MN9/grooming/turning flag。
视觉 引用 Lappalainen et al. 的视觉运动通路模型，并将视觉激活接入 LIF，但 Eon 也承认当前视觉对行为输出偏装饰性。 第一版不做视觉；如需亮点，可只显示摄像头画面和一个 looming/escape 占位事件。
身体 使用 NeuroMechFly v2，一个基于 MuJoCo 的具有关节、接触、力和执行器的成年果蝇身体模型。 直接使用 FlyGym 官方控制器，优先选 turning/hybrid locomotion，少改底层动力学。
脑-身同步 Eon 文章称脑和身体同步约每 15 ms 一次，但也说明该时间步对某些行为可能偏慢。 课堂 MVP 可以用 50-100 ms 控制周期，报告中说明这是工程近似。
下降神经元接口 用少数 descending outputs 控制低层身体控制器，例如 DNa01/DNa02 转向、oDN1 前进速度、MN9 进食、antenal DN 梳理。 实现一个 BrainBridge 类，把脑读出映射成 forward_speed、turn_bias、grooming、feeding。

MVP 架构

最小系统应把科学可信度和工程可演示性分开：身体控制采用 FlyGym 已有控制器，脑模型只负责行为门控和状态读出。 这样课堂上能清楚回答“哪些是复现，哪些是简化，为什么简化”。

1. 环境 MuJoCo/FlyGym 场景中放置食物源、尘埃触发区和起点，记录位置、距离和传感状态。
2. 感觉编码 左右 taste/odor 梯度、proboscis/leg contact、dust flag 转换为神经输入标签。
3. 脑读出 查询 LIF 预计算结果或轻量 surrogate，得到 MN9、grooming DN、turning DN、oDN1 的活动强度。
4. 身体控制 将读出映射为前进速度、转向偏置、停止、梳理片段、进食片段。
5. 可视化 输出视频和状态面板：sensor input、brain readout、selected behavior、position。

模块拆解

模块 建议实现 关键输出
环境与安装 建议优先独立环境：flygym-env 运行 FlyGym/MuJoCo，brain-env 运行 Brian2 全脑模型。 FlyGym 官方文档支持 pip install flygym 和 pip install flygym[examples]。 安装日志、pip freeze、一个官方 tutorial 可跑通。
FlyGym 身体演示 从 turning locomotion controller 或 hybrid locomotion controller 起步，少改内部控制参数。 10-20 秒行走/转向视频，确认渲染正常。
场景构建 创建简化 arena：起点、食物坐标、尘埃区域、边界；食物可以是 invisible cue，不需要复杂碰撞体。 环境配置文件和一张场景截图。
感觉编码 计算左右传感差值：left_cue、right_cue、food_contact、dust_level。 每一帧的 sensor log，便于答辩说明。
脑模型离线读出 复用 Shiu 仓库，分别跑 sugar GRN 和 JON/mechanosensory 输入，提取 MN9 与 grooming 相关输出 firing rate。 brain_lookup.csv 或 brain_lookup.parquet。
BrainBridge 将传感状态映射到 readout：turn_bias、forward_speed、grooming_score、feeding_score。 一个小型 Python 类和单元测试/日志验证。
行为调度器 优先级建议：grooming 高于 foraging；feeding 在 food_contact 时触发；foraging 默认运行。 有限状态机图和行为切换日志。
演示与报告 录制视频，叠加或旁边展示状态面板；报告中标明哪些来自论文模型，哪些是工程近似。 视频、截图、最终 PPT 和答辩问答。

风险与备选方案

风险 表现 处理策略
FlyGym 安装或渲染失败 MuJoCo、OpenGL、macOS 图形环境或依赖版本冲突。 先用官方 notebook/Colab 或只录制 headless 视频；保留已下载官方演示作为讲解参考，但注明不是自复现结果。
全脑 LIF 太慢 每次输入需要数分钟，无法实时联动物理仿真。 使用离线 lookup table，把运行成本变成前处理；实时环路只查表。
脑-身映射不生物精确 MN9、DNa01/DNa02、oDN1 到身体动作的映射不是完整运动层级。 报告中明确这是低维 readout layer，和 Eon 公开文章的简化口径一致。
演示行为不稳定 虚拟果蝇走偏、翻倒、到不了食物源。 缩小场景、降低速度、用预设转向脚本兜底；最终汇报可以播放稳定录屏。
老师质疑“这不是真复现 Eon” Eon 没有公开完整代码，MVP 使用了手写桥接逻辑。 主动说明复现层级：公开组件复现 + 桥接逻辑自实现 + 科学局限分析。这样比模糊宣称更可信。

汇报演示设计

演示脚本
  1. 虚拟果蝇从起点出发，默认处于 foraging。
  2. 左右 cue 差值让 turning controller 偏向食物方向。
  3. dust level 达到阈值后，BrainBridge 切换到 grooming，短暂停止前进。
  4. 梳理后恢复 foraging，接近食物后触发 sugar contact。
  5. MN9 readout 升高，状态切换为 feeding，演示结束。
屏幕元素
  • 左侧：FlyGym/MuJoCo 虚拟果蝇视频。
  • 右侧：sensor input、brain readout、behavior state。
  • 底部：时间轴，标注 dust、grooming、food contact、feeding。

答辩话术

问题 回答重点
最小演示和 Eon 的关系是什么？ 复现的是 Eon 文章公开的系统结构：感觉编码、全脑模型读出、低维下降控制、虚拟身体反馈。Eon 内部代码未完全公开，所以我们做的是可解释的最小实现。
为什么不实时跑全脑？ 全脑 LIF 模型本身计算量大，Nature 代码更适合离线扰动实验。为了课堂演示稳定，我们把全脑模型输出预计算成表，实时仿真只查表。
这是否证明数字生物能控制身体？ 不能过度解释。它证明的是：连接组约束脑模型可以作为一个行为读出模块接入虚拟身体，但完整感觉、内在状态、学习和运动层级仍缺失。
制造物联网有什么借鉴？ 这和工业数字孪生类似：复杂设备拓扑对应连接组，传感事件对应感觉输入，控制器对应执行层，关键是版本化数据、离线仿真、在线查表和闭环验证。
